# 交规扣分内容扩容任务说明

> 背景：用户核对后发现「交规扣分」只收录了 20 条精炼卡片，而《道路交通安全违法行为记分管理办法》（公安部令第 163 号）第八至十二条共有 **50 条** 记分行为；并且用户要求 **原文必须是法条原文**。本次要把「交规扣分」升级为：**50 条记分行为 + 5 条记分规则，全部原文逐字来自法规**。

## 1. 法规版本

- 法规：《道路交通安全违法行为记分管理办法》（公安部令第 163 号），2021-12-17 发布，**2022-04-01 起施行**。
- 截至 2026-10-21 核对，该办法仍为现行有效版本；没有检索到更新/替代的记分办法。
- 官方来源：
  - 公安部：<https://app.mps.gov.cn/gdnps/zc/content.jsp?id=8282949>
  - 国务院公报：<https://www.gov.cn/gongbao/content/2022/content_5679697.htm>
- 机读原文（唯一事实来源）：`docs/sources/score-points-163.json`。**不要修改它**；若发现其中文字与官方链接不一致，立即报告 Lead，不要自行改。

## 2. 分区与文件

每个负责人只写自己的一个文件：

| 分区 | 负责文件 | 内容 | 卡片 id | 题目 id |
|---|---|---|---|---|
| partA | `src/data/deduction-parts/partA.ts` | 12分 7 条 + 9分 7 条 | dd-01…dd-14 | qdd-01…qdd-14 |
| partB | `src/data/deduction-parts/partB.ts` | 6分 11 条 | dd-15…dd-25 | qdd-15…qdd-25 |
| partC | `src/data/deduction-parts/partC.ts` | 3分 15 条 | dd-26…dd-40 | qdd-26…qdd-40 |
| partD | `src/data/deduction-parts/partD.ts` | 1分 10 条 + 记分规则 5 条 | dd-41…dd-55 | qdd-41…qdd-55 |

最终会合并为：`12分 7 / 9分 7 / 6分 11 / 3分 15 / 1分 10 / 记分规则 5 = 55 张卡`，题目与卡片一一对应，共 55 题。

## 4. 逐字原文（最重要）

- 每张卡的 `original` 必须与 `docs/sources/score-points-163.json` 中对应条目**逐字一致**，包括：
  - 开头的 `（一）`、`（二）` 等编号；
  - 结尾的 `；` 或 `。`；
  - “百分之二十”“4小时”“20分钟”等写法；
  - 所有标点（全角括号、句号、分号、顿号）。
- 每张卡的 `source` 也由脚本给出，必须逐字复制，例如：
  - 行为卡：`《道路交通安全违法行为记分管理办法》第八条第（一）项`
  - 规则卡：`《道路交通安全违法行为记分管理办法》第三条`
- **禁止**精简、改写、合并、补全原文；卡片标题负责“说人话”，原文负责“给依据”。
- 规则卡（partD 后 5 条）的原文是整段法规条文，也必须逐字复制（脚本已把同一条的多个自然段拼成一个字符串，照抄即可）。

获取你负责分区的内容（不要自己猜）：

```bash
npx tsx scripts/print-deduction-source.ts partA   # 换成你的分区
```

## 5. 卡片标题与辅助记忆

- 标题 2-20 字，直接概括违法行为，例如「高速倒车、逆行」「事故逃逸（轻伤以上）」「不按规定避让校车」。
- 辅助记忆 8-100 字，必须是真的记忆抓手：分档对比、数字口诀、场景联想、与相邻档位的区别。禁止只复述原文，也不要引入未经核实的其他处罚金额/拘留天数（那些属于「交规罚钱」，不在这张卡的范围）。
- 同一分区内标题不能重复、记忆不能重复；不要写 Markdown、emoji、换行。

## 6. 题目要求（每题对应一张卡，顺序一致）

- 数量固定：**一张卡对应一道题**，题目顺序与卡片顺序一致，`group` 与对应卡片相同。
- 形式尽量多样，不要 55 题全是“一次记多少分”：
  - 分值题：某行为一次记多少分；
  - 场景题：给定车型/道路/比例/能见度等条件，判断记分；
  - 归类题：“下列哪种行为一次记 9 分？”（干扰项必须确实不是 9 分）；
  - 对照题：两个相近档位的行为对比；
  - 规则题（partD）：围绕记分周期、清零、满分学习、学法减分。
- 正确项必须能由对应卡片原文直接支持；干扰项必须**确定错误**、无歧义；避免“以上都对/都不对”，避免选项之间互相包含。
- 题干 8-100 字，解析 12-160 字；解析要写「依据 + 易错点」，不要只写“选 A”。
- 正确项分布要打散：每个分区内 A/B/C/D 各至少出现 2 次，单一位置不超过 60%；能写到大致均衡最好（如 14 题 4/4/3/3）。
- 数字、车型、道路类型、百分比必须与对应条目严格一致。

## 7. 自检

只允许改自己的 part 文件。不要修改 `deduction.ts`、`types.ts`、其他 part、UI、docs、canonical JSON。

```bash
npx tsx scripts/validate-deduction-part.ts partA   # 换成你的分区，必须通过
```

通过后会输出 `卡片 N/N，题目 N/N`。不要运行 `npm run build` / 全量 `validate-data`（Lead 正在并行合并其他分区）。若要单独类型检查：

```bash
npx tsc --ignoreConfig --noEmit --strict --target ES2022 --module ESNext --moduleResolution Bundler --skipLibCheck src/data/types.ts src/data/deduction-parts/partA.ts
```

完成后：更新共享任务为完成，并给 Lead 发一条简短汇报：分区、卡片/题目数量、分组分布、答案分布、校验结果、任何存疑点。内容直接面向备考用户，宁可多核对一遍数字，也不要出现一处与法条不符。
